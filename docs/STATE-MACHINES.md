# Folio workflow state map

This map separates user-visible workflows, asynchronous operations, persisted lifecycles, and independent preferences. A boolean is not inherently a bug; filters, text inputs, and selections are context rather than automatically separate state machines.

## Decision

Keep the existing authoritative backend transitions and reservations. Make mutually exclusive UI modes explicit with small pure reducers; retain independent state for independent controls. Do not add a state-machine framework or move provider work into React reducers. The server remains the authority for ownership, authorization, payment reservations, and verified outcomes.

The first focused changes are the social studio reducer and the shared action button's synchronous in-flight guard. They remove contradictory UI states and same-turn duplicate activation without changing the managed provider protocol or database schema.

## Reproducible inventory

Run `bun run state:audit` for a compact file inventory, or `node scripts/state-machine-audit.mjs --json` for structured candidates with source locations on hook slots, external subscriptions, and native/library controls. This scans tracked source directories (`src`, `workers`, `migrations`, `analytics-migrations`), not environment files, local databases, credentials, or provider records. It performs no network requests.

The scanner finds React state/reducer slots, tagged status contracts, operation/identity refs, SQL lifecycle/concurrency guards, database triggers, URL/session subscriptions, and native disclosure/select controls. The JSON output is suitable for an agent to locate implementation and inspect transitions. It is an index, not an authoritative API for deciding whether a paid action is allowed.

Static detection cannot prove runtime reachability, discover every aliased hook, or enumerate state hidden inside third-party libraries or providers. The reviewed families below cover those boundaries too. Regenerate the inventory after changes rather than relying on a frozen count or a giant generated report in Git.

## Cross-cutting transition rules

1. **Owner identity is part of the machine.** Abort reads and clear private context on logout or owner change. Ignore late responses, including successful responses from the previous owner. A run ID or query parameter is never authorization.
2. **Distinguish operation from evidence.** Loading, request accepted, provider completed, verifier passed, stored, and published are different milestones. UI labels and agent outputs should describe the milestone actually established.
3. **Keep uncertainty visible.** Empty, not measured, partial, failed, stale snapshot, unknown identity, and unknown cost are different outcomes.
4. **Commands need explicit intent.** Prepare/open/filter/read actions may not create a paid task. Server guards remain authoritative even when a client button looks disabled.
5. **Use synchronous locks for side effects, reducers for presentation.** A reducer is pure and replayable. React state alone is not a same-turn mutex; backend reservations and revision guards remain necessary across tabs/processes.
6. **Represent parallel regions honestly.** Loading one report while viewing another is valid. Do not flatten independent collection states into one global loading flag or enumerate every filter combination as a lifecycle state.
7. **Keep transport semantics stable for agents.** Inspect current owned records and readiness before issuing a command; use existing structured errors and statuses. Do not infer allowed actions from a screenshot, an animation, or this static inventory.

## Validation and boundaries

The reducer tests cover mode transitions, immutable inputs, destination/copy invalidation, and closed/empty save guards. The browser regression triggers the shared save control twice in one JavaScript turn and checks one analytics event, accurate saved status after a destination change, and absence of unrelated writes. Existing desktop/mobile social, analytics, and sidebar checks exercise the integrated component.

This pass does not migrate backend lifecycle storage, change provider protocols, add automatic retries, or authorize new spending. Unit/browser fixtures are not live provider validation or proof that every reachable app state has been exercised. Future migrations should start from a concrete contradiction or regression, preserve persisted schemas and error contracts, and add transition-level tests before replacing existing state.
